## 一、项目概述

「小食记」是一个为情侣定制的点菜小程序：一方（**女友 / 点菜端**）浏览菜单、挑菜、备注口味、下单；另一方（**你 / 大厨端**）接单、备菜、上菜。设计走**温馨、克制、原木自然（抹茶绿）**风格，语言亲切但不肉麻。

目标形态：**微信小程序**（原型是手机尺寸 375-ish 竖屏）。也可先做 H5 / App，后续迁小程序。

核心功能：
- 选菜（分类筛选、加入购物车、数量增减）
- 菜品详情（调辣度、填忌口/备注）
- 购物车抽屉 + 给大厨留言 + 下单（带加载态）
- 添加新菜（上传照片 / 选图标、分组、辣度、描述）
- 长按菜品编辑/删除；长按分组改名/删除
- 常点、买菜清单、点菜记录（记录页分段 Tab）
- 「今天吃什么」随机转盘（带抽奖动画）
- 双端切换（右上角悬浮按钮）
- 大厨端：接单 → 备菜中 → 已上菜 的状态流转

## 五、屏幕 / 视图

所有视图共用一个手机外壳：顶部状态栏（9:41 / 信号电量）、微信风格标题栏（居中标题 + 可选返回 ‹ + 右上胶囊 ···○）、中间滚动区、底部条（购物车条 / 操作条 / TabBar，视场景显示）。

### 1. 点菜首页（menu）
- **问候语区**：大标题「亲爱的，慢慢挑～」+ 副标题「想吃什么都记下来，我一样样做给你 🌿」。
- **「今天吃什么」卡片**：左侧 🎲 圆角图标，中间标题+说明，右侧一个**静态**粗圆头 `>` 箭头（SVG，stroke `#a8b090` width 3.2）。点击打开随机转盘。
- **分类 chip 行**：横向可滚动。`全部` + 各分组。选中态 `.chip.on`（sage 实底白字）。**长按非「全部」的分组** → 打开分组编辑弹窗。
- **提示行**：小字「长按菜品可编辑 · 长按分组可改名/删除」。
- **菜品列表**：每行 = 左缩略图(66px) + 中(菜名/描述/辣度) + 右加减控件。
  - 未加入：空心圆角 ＋ 按钮（`.addbtn.hollow`）。
  - 已加入：`− 数量 ＋` 步进器（`.step`，方形 sage 按钮）。
  - 点缩略图或菜名 → 进入详情。**长按整行** → 进入编辑（复用「添加新菜」表单）。
- 底部：**购物车条** + **TabBar**。

### 2. 菜品详情（detail）
- 顶部 190px 大图区（缩略背景放大，emoji 70px）。
- 菜名(20/900) + 描述。
- **辣度**：4 个 chip（不辣/微辣/中辣/重辣），单选，写入该菜的 note.spice。
- **忌口 / 悄悄话备注**：多行文本框，写入 note.forbid。
- 底部操作条：主按钮「加入这道菜 🌿」→ 加购并返回首页。

### 3. 购物车抽屉（drawer，从底部滑起）
- 由购物车条左侧（🛒+文案）点击唤起；`animation: slideUp .3s`。
- 顶部小把手 + 「我点的菜 · N 道」+ 关闭 ×。
- 菜品卡列表（缩略图 + 名称 + 该项备注 cartNote + 步进器）。
- 「给大厨留张小纸条 💌」文本框（写入 order.msg）。
- 底部主按钮「下单 · 让大厨开火 🍳（N 道）」。
- 购物车条右侧的「去下单」按钮**直接下单**（不开抽屉）。

### 4. 下单加载（loading，全屏遮罩）
- **自定义 SVG 图标**：手绘线性「煮锅」，三缕热气分别以 `steamRise`（错开 0/.5/1s）循环上升，锅身 `bob` 轻微起伏。文案「正在送往大厨…」。约 950ms 后进入成功页。

### 5. 下单成功（done）
- 🧑‍🍳 emoji（`wob` 摇摆）+「订单已送到大厨手机啦」+「大厨已接单…」。
- 订单摘要卡：每项 `菜名 + 备注 ×数量`，末尾留言。
- 「再点一桌 🍚」/「看看点过的菜 ›」。

### 6. 添加 / 编辑新菜（add）
- 标题：新增时「加一道新菜」，编辑时「编辑菜品」。
- 字段：菜名 → 配图（**上传照片** label+file input，或**选图标**网格 `🍚🍜🍲🥘🍳🥟🥬🍗🦐🐟🍅🌶`）→ 分组 chip（含「＋新建分组」内联输入）→ 辣度 chip → 一句话描述。
- 主按钮：新增「加进菜单 🌿」/ 编辑「保存修改 ✏️」；编辑态下方有「删除这道菜」。
- **注意**：AI 生图功能已移除，仅保留上传/图标。（见第九节的可选扩展。）

### 7. 记录（orders，分段 Tab）
顶部三个 chip Tab：**常点 ⭐ / 买菜清单 🛒 / 点菜记录 📖**，切换有 `fade .25s`。
- **常点**：`fav` 菜的 chip，点击加入购物车并 toast「「X」已加入清单 🌿」。
- **买菜清单**：输入框+「加」；每条带方形复选框（勾选划线置灰）+ 删除 ×。
- **点菜记录**：订单卡，含时间、**状态徽标**、每项(名称+备注 ×数量)、留言。

### 8. 大厨端（chef side）
- 由右上角悬浮按钮切换进入；标题「大厨端」，左侧返回 ‹ 回点菜端。
- 「收到的点单」+「N 桌待处理」徽标。
- 订单卡：时间、状态徽标、条目(名称+备注)、留言，+ **推进按钮**：
  - 待接单 →「接单开做 🍳」→ 备菜中
  - 备菜中 →「标记上菜 🍽」→ 已上菜
  - 已上菜 → 显示「已上菜 ✓ 慢慢吃～」
- 空态：☕「还没有人点单，先歇会儿～」。

### 9. 双端切换悬浮按钮（FAB）
- 右上角（`top:76px; right:14px`）52×52 sage 圆角方块，白色线性图标 + 小字标签。
- 点菜端：显示**锅铲/锅**图标 +「大厨端」；大厨端：显示**饭碗**图标 +「点菜端」。
- 仅在（点菜端首页）或（大厨端）显示。放右上是为避开右侧「＋」加菜按钮列。

### 10. 随机转盘弹窗（today）
- 标题「🎲 今天就吃」。
- **抽奖动画**：`rolling` 阶段——🎲 旋转(`spin`)、背后菜品 emoji 模糊淡显、文案「让我想想…」脉冲(`pulse`)；快速切换 randomId 约 13×85ms 后停。
- 停后 `reveal` 弹出菜品缩略/菜名/描述 + 「换一个 🎲」/「就它啦 🌿」（加购）。

| 名称 | 触发 | 规格 |
|---|---|---|
| 加菜飞入购物车 | 点菜单里的 ＋ | 元素从按钮沿**左上四分之一圆弧**飞向购物车图标：`x=dx·sin(θ)`, `y=dy·(1−cos θ)`, θ:0→90°，10 帧，700ms，`ease-in`；落点购物车图标 `scale 1→1.4→1` 320ms。 |

## 七、状态与数据

### 前端状态（原型用单组件 state，实现时按框架拆分）
- `side`: 'guest' | 'chef'（当前端）
- `screen`: 'menu' | 'detail' | 'cart' | 'done' | 'add' | 'orders'
- `cat`: 当前分类；`groups`: 分组数组
- `cart`: `{ dishId: qty }`
- `notes`: `{ dishId: { spice:0-3, forbid:string } }`（下单后清空）
- `dishes`: 菜品数组
- `orders`: 订单数组（最新在前）
- `msg`: 当前留言草稿
- `detailId` / `editId` / `randomId`：当前操作对象
- `showRandom` / `rolling` / `drawer` / `loading`：各弹层/态
- `shopping`: 买菜清单；`shopText`：草稿
- `orderTab`: 'fav' | 'shop' | 'hist'
- `groupEdit`: `{ open, orig, text }`
- `toast`

### 关键状态转移
- 加菜：`cart[id]++`（首页/详情/常点/转盘）；减：`cart[id]--`，为 0 则删。
- 下单 `placeOrder`：cartCount>0 → `loading=true` → 950ms → 生成 order（status '待接单'，items 带 note）插入 orders 头部 → 清空 cart/msg/notes → screen='done'。
- 大厨推进 `advanceOrder`：待接单→备菜中→已上菜。
- 编辑菜 `editDish`：把 dish 灌进表单+`editId`；`submitDish` 有 editId 则更新，否则新增。
- 分组：改名同步更新 dishes 的 cat 与当前 cat；删除把该组菜归到剩余首个分组，至少保留 1 个分组。

## 八、后端数据模型 & API（建议）

原型是纯前端内存态。落地需真实后端。推荐把两端做成**同一小程序内的双角色**，共享一个「情侣空间（couple/家庭）」的数据。

### 数据模型
```
User        { id, openid, nickname, avatar, role: 'cook'|'orderer', coupleId }
Couple      { id, members:[userId], createdAt }           // 一个情侣空间
Group       { id, coupleId, name, sort }                  // 菜品分组
Dish        { id, coupleId, name, groupId, spice:0-3,
              desc, imageUrl|iconEmoji, isFav:bool,
              createdBy, createdAt, deletedAt? }
Order       { id, coupleId, createdBy, createdAt,
              status:'pending'|'cooking'|'served',         // 待接单/备菜中/已上菜
              message, items:[OrderItem] }
OrderItem   { dishId, name, qty, spiceLabel, forbid }      // 下单快照，含备注
ShopItem    { id, coupleId, text, done:bool, createdAt }   // 买菜清单
```
> `OrderItem` 存**快照**（名称/备注），避免菜品后续被改/删影响历史。

### API（REST 示例；小程序云开发可换成云函数同名）
```
# 菜单 & 分组
GET    /dishes?groupId=&fav=            列出菜品（软删除过滤）
POST   /dishes                          新增菜（name, groupId, spice, desc, image/icon）
PATCH  /dishes/:id                      编辑
DELETE /dishes/:id                      删除（软删）
GET    /groups                          列分组
POST   /groups                          新建分组 {name}
PATCH  /groups/:id                      改名
DELETE /groups/:id                      删除（后端把该组菜迁到 fallback 组；禁止删到 0 组）

# 购物车（可仅前端本地，或存服务端草稿）
# 下单
POST   /orders                          下单 {items:[{dishId,qty,spiceLabel,forbid}], message}
GET    /orders                          订单列表（按时间倒序）
PATCH  /orders/:id/status               大厨推进 {status}
                                        （建议服务端校验状态机顺序）

# 买菜清单
GET    /shop-items
POST   /shop-items                      {text}
PATCH  /shop-items/:id                  {done}
DELETE /shop-items/:id

# 图片
POST   /upload                          图片上传（返回 imageUrl；小程序用云存储/OSS）
```

### 实时性（推荐）
大厨端要能**实时收到新单**、点菜端要能看到**状态变化**。建议：
- 微信云开发：数据库 **watch** 监听 orders 变化。
- 或自建：WebSocket / 订阅推送 + 微信**订阅消息**（新订单通知大厨、上菜通知女友）。

### 鉴权 & 角色
- 微信 `code2Session` 换 openid 登录；首次绑定到同一 `coupleId`（邀请码/扫码绑定）。
- 角色 `role` 决定默认落地端；FAB 仍可切端预览。真实里大厨端建议只有 cook 能推进订单状态。

## 九、可选扩展：AI 配图（用户后续接入）

用户希望「加新菜时按菜名生成配图」。**注意：DeepSeek 目前只有文本/对话模型，没有文生图**。落地方案：
1. DeepSeek（或任意 LLM）把菜名润色成绘图 prompt（如「荷兰豆炒腊肠，暖光，家常菜特写，浅景深」）。
2. 调用**图像生成模型**（通义万相 / 即梦 / SD 等）拿到图片，存入云存储，写回 `Dish.imageUrl`。
3. 前端在「配图」区加一个「✨ AI 生成」按钮，调用后端 `POST /dishes/ai-image {name}`，期间显示第 4 屏那种加载态。
> 原型已移除该按钮；在 `submitDish` / 配图区预留接入位即可。API key 由用户提供，务必放**后端**，不要写进小程序前端。
